# 반품요청 기능 설정 가이드

사용자가 마이페이지 발주 내역에서 반품을 신청하고, 환급계좌를 포함한 신청 정보가
관리자 메일로 전송되는 기능입니다.

배포 전 아래 **2가지 준비**가 반드시 필요합니다.

---

## 1. Supabase 테이블 생성

Supabase Dashboard → **SQL Editor** → New Query 에 아래 파일 내용을 붙여넣고 실행하세요.

```
docs/migrations/2026-09-02-return-requests.sql
```

`return_requests` 테이블과 인덱스, `updated_at` 자동 갱신 트리거가 생성됩니다.

> **왜 RLS 를 켜고 anon 권한을 회수하나요?**
> 이 테이블에는 **은행 / 계좌번호 / 예금주**가 들어갑니다.
> `NEXT_PUBLIC_SUPABASE_ANON_KEY` 는 브라우저에 그대로 노출되므로,
> anon 키로 읽을 수 있게 두면 누구나 다른 고객의 계좌번호를 조회할 수 있습니다.
> 그래서 anon 접근을 막고, 서버에서 `service_role` 키로만 접근합니다.

---

## 2. 환경변수 추가

`.env.local` (및 배포 환경의 환경변수)에 **service_role 키**를 추가합니다.

```bash
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
```

키 위치: Supabase Dashboard → **Project Settings → API → Project API keys → `service_role`**

> ⚠️ service_role 키는 RLS 를 우회하는 마스터 키입니다.
> 절대 `NEXT_PUBLIC_` 접두사를 붙이지 말고, 저장소에 커밋하지 마세요.

### 이미 설정되어 있어야 하는 값

| 변수 | 용도 |
|------|------|
| `SUPABASE_URL` / `SUPABASE_ANON_KEY` | 서버 측 일반 조회 (발주 내역 등) |
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 브라우저 사진 업로드 |
| `NAVER_USER` / `NAVER_PASS` | 네이버 SMTP 메일 발송 |
| `ADMIN_EMAIL` | 반품 알림 수신 주소 (미설정 시 `swchoi157@naver.com`) |

## 동작 흐름

```
마이페이지 발주 내역
  └ [반품요청] 버튼  →  /mypage/return/{주문번호}
                         ├ 1. 반품 상품·수량 선택 (발주 수량 초과 불가)
                         ├ 2. 반품 사유 선택 + 상세
                         ├ 3. 증빙 사진 (최대 4장, community-images 버킷)
                         ├ 4. 환급 계좌 (은행/계좌번호/예금주)
                         └ 5. 회수지 주소 (기본값 = 발주 시 배송지)
                              ↓ 접수
                    return_requests 테이블 저장
                              ↓
              ┌───────────────┴───────────────┐
        관리자 메일 (계좌 전문 포함)      고객 확인 메일
                              ↓
                  /admin/returns 에서 상태 관리
                  접수 → 승인 → 회수중 → 환불완료 / 반려
```

## 검증 규칙

- 로그인 사용자의 **본인 주문**만 신청 가능 (`quotes.user_id` 대조)
- 반품 수량은 발주 수량을 초과할 수 없음
- 이미 신청된 수량과 합산해서도 초과 불가 (부분 반품 여러 번 신청 대응)
- 반려(`rejected`)된 건은 수량 합산에서 제외되어 재신청 가능
- 계좌번호는 숫자 10~16자리, 은행은 지정 목록만 허용
- 동일 검증 로직(`lib/returns.ts`)을 클라이언트·서버 양쪽에서 실행

## 메일 발송 실패 시

DB 저장이 먼저 이뤄지므로 **메일이 실패해도 접수는 유효**합니다.
이 경우 고객 화면에 안내 문구가 뜨고, 관리자는 `/admin/returns` 에서 그대로 확인할 수 있습니다.

## 관련 파일

| 파일 | 역할 |
|------|------|
| `lib/returns.ts` | 사유·상태 상수, 공용 검증 로직 |
| `lib/return-requests.ts` | 서버 전용 데이터 접근 (service_role) |
| `lib/supabase-admin.ts` | service_role Supabase 클라이언트 |
| `lib/emails/return-request.ts` | 관리자·고객 메일 HTML |
| `app/api/returns/route.ts` | 접수(POST) / 목록(GET) |
| `app/api/returns/[id]/route.ts` | 관리자 상태·메모 변경(PATCH) |
| `app/mypage/return/[orderNumber]/` | 반품 신청 화면 |
| `app/admin/returns/page.tsx` | 관리자 반품요청 관리 |
